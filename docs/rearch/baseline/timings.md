## The two costs that are contracts, not noise

The top of that table is not a performance problem to be optimised away.
Both leaders are deliberate, and each has a named production change that
would make it cheap — which is the only thing that should make it cheap.

- **`error_contract` is dominated by one row.** `LockTimeout` provokes a
  *real* lock timeout, and `with_project_lock` polls a hard-coded 5s deadline
  (`src/lock.rs`) with no environment override. Both output forms are
  provoked concurrently so the wait is paid once (11.1s → 5.9s) instead of
  twice. **If W5 makes that deadline configurable, this binary drops to ~1s**
  and the gate drops with it. Until then it is the price of pinning exit 4
  at all, and exit 4 is part of the interface.
- **`golden_cli` carries a deliberate `>=1s` sleep.** 177 CLI invocations
  across 27 snapshots, plus one sleep placed so that every same-priority
  ready PAIR straddles it. That sleep is the workaround for the
  nondeterministic ready-list ordering (`docs/rearch/STATE.md`, W0.3 finding
  #1): `created_at` has second precision, so stories created within one
  second tie on both sort keys. **The sleep goes away when the comparator
  gets a total order**, not before.
- **`web_test` runs real servers.** Ports are kernel-assigned and daemons are
  stopped by a guard (SH-51); the cost is genuine I/O against genuine HTTP,
  which is the point of the file.

Those first two account for most of the gap between the ~29s gate before W0.3
and the gate measured above. Neither is a regression.
