# The pre-rearchitecture baseline

This directory is the *before* picture. Everything in it except this file is
generated by `scripts/capture-baseline.sh` and should be regenerated, not
edited:

```sh
scripts/capture-baseline.sh                    # full capture, ~10 minutes
scripts/capture-baseline.sh --skip-census      # everything but the 10 make-test runs
scripts/capture-baseline.sh --out /tmp/after   # capture elsewhere, then diff
```

## Why it exists

The data-layer rearchitecture replaces the storage engine underneath a CLI
whose observable behaviour *is* its contract. Nothing about that work is
type-checked end to end: a service seam can turn a `NotFound` into a `Storage`,
a daemon hop can move a message from stderr to stdout, and an importer can drop
a field that only one archived story ever used. None of those break a build.

So the defence is a *before* picture precise enough to diff an *after* picture
against. Re-run the script at a wave boundary and `git diff` is the report — a
test that silently stopped existing is a removed line, not a mystery.

## What is here

| file | what it pins | who consumes it |
|---|---|---|
| `manifest.json` | machine tag, counts, and a sha256 for every artifact | any later capture, for provenance |
| `test-inventory.txt` | every test NAME, per binary, plus the bash suite | every wave — a vanished test is a diff |
| `known-red.md` | the `#[ignore]`d tests and what un-ignores them | W4, whose exit criterion is in here |
| `error-codes.md` | variant → exit code → stream → envelope shape | W0b (envelope), W2 (services), W5 (daemon) |
| `timings.json` / `.md` | per-binary and whole-gate wall times | every wave, as a cost regression check |
| `flake-census.md` | 10 consecutive `make test` runs, per-test accounting | every wave — the definition of "green" |
| `legacy-tree.tar.gz` | this repo's own `.storyhook/`, frozen | **W3**, the importer |
| `legacy-tree.txt` | that tarball's contents, so the blob is reviewable | humans reading a diff |
| `golden-export.json` | `story export` of that same tree | **W3**, as the import oracle |
| `archive-schema.sql` | the legacy archive DB, defined as schema version 0 | **W1**, the migration framework |

## The legacy tree is a real fixture, and it is verified

`legacy-tree.tar.gz` is the tracker storyhook uses to track itself: **61 stories
and 486 events**, accumulated over the project's whole life. 17 stories are open
as JSONL event logs; 44 are closed, living in the archive database (43
`StoryClosedAndArchived` plus one `StoryDeleted`). The event mix is what makes
it valuable — no synthetic fixture reaches this shape by accident:

| event kind | count |
|---|---|
| `StoryRelationshipAdded` | 132 |
| `StoryStateChanged` | 72 |
| `StoryCommentAdded` | 67 |
| `StoryCreated` | 61 |
| `StoryClosedAndArchived` | 43 |
| `StoryPrioritySet` | 41 |
| `StoryLabelsSet` | 26 |
| `StoryTypeSet` | 21 |
| `StoryDescriptionSet` | 16 |
| `StoryAwaitingSet` | 5 |
| `StoryTitleSet` | 1 |
| `StoryDeleted` | 1 |

**Know what it does NOT cover.** Its 5 states and 5 types are the *defaults*
(`todo`/`in-progress`/`verifying`/`blocked`/`done`,
`story`/`epic`/`bug`/`chore`/`task`), and `members` is **empty**. So this tree
proves nothing about importing custom states, custom types, or member records.

That gap is covered from the other side:
`tests/story_export.rs::export_import_export_is_byte_identical` builds a small
synthetic project that deliberately adds a custom type (`spike`), a custom state
(`review`) and a member (Ada Lovelace), then asserts a byte-identical round
trip. **The two fixtures are complementary and W3 needs both**: one has depth and
history no synthetic fixture can fake, the other has the configuration surface
real data happens never to have used.

The tree was validated at capture time by restoring it and proving three things
— it is a working project, its export *is* the golden document, and that
document survives a full import→export round trip byte for byte:

```sh
BASE=$PWD/docs/rearch/baseline          # from the repo root

mkdir /tmp/legacy && tar -xzf "$BASE/legacy-tree.tar.gz" -C /tmp/legacy
(cd /tmp/legacy && story list && story export | diff - "$BASE/golden-export.json")

mkdir /tmp/round
(cd /tmp/round && story import-project "$BASE/golden-export.json" \
  && story export | diff - "$BASE/golden-export.json")
```

That third property is W3's target: the importer must round-trip this document
without losing a byte.

**W3 result, for anyone diffing a later capture.** `story migrate` reproduces
this tree exactly, with one documented set of differences and one contract
quirk:

- **Ten repair events**, and they are the fifteen live SH-60 violations this
  tree has carried for months. Ten relations are claimed by only one end; five
  of them are completed with the missing event, and the other five are
  *unilateral parent claims* that are retracted instead, because completing
  them would give SH-32 through SH-36 two parents each — which the store
  refuses. `tests/migrate_round_trip.rs::the_real_trees_export_equals_the_
  golden_document_modulo_the_repairs` asserts that every golden event is still
  present in order and that every extra one is a repair the migration report
  names. 486 events in, 496 out.
- **`prefix` reads `null` rather than `"SH"`** in the store's export. Contract,
  not loss: `story export` emits `null` for the default prefix, and this
  project happens to have been initialized with an explicit `--prefix SH`. Both
  documents import to the same project.

The tree also exercises the reader's refusals by *not* triggering them: every
event kind in it is one this binary understands, no story exists twice, no
relation dangles, and every state slug it names is configured. The synthetic
fixture in `tests/legacy_support/mod.rs` is where the broken shapes are built.

## Yes, there is a binary blob in git

`legacy-tree.tar.gz` is ~40KB of gzip committed to a repository that otherwise
holds nothing but text. That is deliberate and narrow: it is a *frozen fixture*
in `docs/`, not live data, and it is written with `gzip -n` so an unchanged tree
produces unchanged bytes and a re-capture is a no-op rather than a new blob.
`legacy-tree.txt` lists every file in it with size and sha256, so the blob is
reviewable without being readable.

The irony is noted: the rearchitecture exists partly because storyhook keeps its
data as files inside the repository it tracks, and the first artifact of the
work is a copy of exactly that, kept as a file inside the repository.

## Reading a later capture against this one

Absolute seconds compare only on the same machine — check the provenance line
in `timings.md` before concluding anything. Ratios compare anywhere. What is
always comparable, on any machine:

- test names in `test-inventory.txt` (additions fine, **removals need a reason**)
- exit codes and envelope key sets in `error-codes.md` (**any change is breaking**)
- the ignored list in `known-red.md` (it should only ever shrink)
- the census verdict in `flake-census.md` (anything but N/N green is a stop)
