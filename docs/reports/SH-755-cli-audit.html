Decision and limits

Use the CLI as the supported agent interface. Keep existing CLI syntax and JSON contracts. Remove the MCP server and its plugin registration; retain an exit-2 migration error and help.

This report audits the v3.0.3 checkout plus SH-755 changes. It is a source-based engineering review, not a user study. SH-752 owns assignee removal. SH-756 owns complexity and model selection. Recheck their final interfaces before the redesign.

SH-757 has priority low and label no-auto. The recommendations below are proposals for approval, not implementation authority. Existing help and commands provide workarounds for these usability costs.

Eight decisions for SH-757

Order reflects design dependencies: define command metadata first, then choose input, output, and discovery contracts. Each item requires approval before a compatibility change.

01

Command discovery

Add a read-only machine-readable command description, generated from the same metadata as help and flag validation.

Evidence: src/cli.rs:1872; src/cli.rs:2517; src/help_topics.rs:13

Caller mistake
An agent must reconstruct the accepted surface from prose. Parser, flag table, and help are separate sources.
Compatibility cost
Additive initially; converting parser metadata is substantial. Keep existing syntax and prove equivalent parsing.
Acceptance
Every runnable command, alias, argument, enum, output mode, and mutation capability is discoverable; drift tests compare discovery with accepted invocations.
02

Separate input and output options

Introduce a distinct JSON input option for set, with a migration period for the current spelling.

Evidence: src/cli.rs:1621

Caller mistake
The same --json token means output selection or an input object, based on the following token. A caller can request the wrong mode.
Compatibility cost
Add a new input spelling first. Warn on legacy use only through an established diagnostics channel; do not contaminate JSON stdout.
Acceptance
Input JSON and output format combine without lookahead ambiguity. Test old and new spellings, invalid JSON, and tokens beginning with {.
03

Literal text and help

Define one end-of-options rule across global scanning, help handling, and each command parser.

Evidence: src/cli.rs:1758; src/cli.rs:2487

Caller mistake
A standalone --help or -h still triggers help after --. Some verb parsers also recognize their own options after it. The guide documents these limits; literal text is not handled consistently.
Compatibility cost
Behavior change for scripts that rely on help taking precedence. Preserve ordinary command --help and test each positional-text path.
Acceptance
The agreed terminator rule works for titles, comments, searches, and option-shaped values. Help requests never mutate data.
04

Stable queue shapes

Choose a queue response whose data shape does not depend on requested count, with an explicit empty result.

Evidence: src/invoke.rs:649

Caller mistake
next uses story, stories, or message. --count 2 can return a list of one. Agents can mistake a valid response for missing data.
Compatibility cost
Changing the existing shape breaks consumers. Introduce a versioned or opt-in contract before any removal.
Acceptance
Zero, one, and many matches have a documented stable shape in the new mode. Existing consumers retain their contract during migration.
05

Audience-aware discovery

Separate task commands, operator recovery, and private workflow protocols in help and machine discovery.

Evidence: src/cli.rs:236; src/cli.rs:2499

Caller mistake
Flat discovery exposes continuation receipts and verifier repair beside ordinary work. A plausible command name can lead to an unauthorized workflow step.
Compatibility cost
Help grouping is compatible. Moving or hiding invocation names needs explicit migration and must not weaken authorization.
Acceptance
A task agent can discover its normal lifecycle without internal protocols. Operators can still find recovery commands; protocol callers stay functional.
06

Aliases and lifecycle vocabulary

Choose canonical names for relationship and lifecycle operations; retain explicit alias metadata and migration hints.

Evidence: src/cli.rs:2648; src/help_topics.rs:158

Caller mistake
link means a story relationship, while project link registers a repository. close, archive, delete, reset, and unclaim have different effects.
Compatibility cost
Prefer documentation and additive aliases first. Any removal needs an actionable refusal and a compatibility window.
Acceptance
Discovery identifies canonical names, aliases, and effects. Tests prevent alias drift and prove that archive, delete, and claim release remain distinct.
07

Explicit output modes

Describe output capability per command; consider explicit document, stream, and delegated modes in the future interface.

Evidence: src/output.rs:1056; src/main.rs:270

Caller mistake
A global --json flag does not imply one envelope. Raw documents, JSON Lines, helper output, and terminal modes need different readers.
Compatibility cost
Keep current streams and fields until callers can opt into a replacement. Do not wrap raw exports or hook payloads silently.
Acceptance
Each command declares stdout, stderr, success, empty, error, quiet, and streaming behavior. Consumer tests cover every declared output class.
08

Mutation capability metadata

Declare confirmation, dry-run, conditional-write support, and uncertain-outcome recovery for each command.

Evidence: src/main.rs:684; src/cli.rs:3572; src/main.rs:75

Caller mistake
Agents may assume --dry-run is universal or retry a timed-out mutation. Current safeguards exist, but discovery does not summarize them.
Compatibility cost
Capability metadata is additive. New preview or idempotency guarantees require a separate design; do not claim them for existing writes.
Acceptance
No command advertises a capability it lacks. Tests cover confirmation refusals, guarded conflicts, preview non-mutation, and lost-reply recovery guidance.

Validation and handoff

The regression tests first failed against the original behavior. Retirement tests cover protocol input, plain and JSON errors, help, no project configuration, no daemon state, and removed plugin registration. CLI tests cover command-aware diagnostics and the production create → comment → claim → guarded-conflict → read flow.

Documentation checks compare help and README usage with the parser. Output checks retain existing fields and test conflict, empty, quiet, and raw-document behavior. The changed-tree selector returned ALL because its baseline has no coverage map. Only new and directly impacted tests run in this worktree; the central verifier owns the full suite.
