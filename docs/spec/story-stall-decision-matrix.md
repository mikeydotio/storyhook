# Story stall and recovery decision matrix

Status: **proposal for implementation; no runtime changes authorized by this document**. Prepared 2026-10-15 for StoryHook v3.0.3. Source snapshot: [`7a06ec099d6af0cae1c329352af54d9972d4e31b`](https://github.com/mikeydotio/storyhook/commit/7a06ec099d6af0cae1c329352af54d9972d4e31b), verified against `mikeydotio/storyhook`'s `dev` branch. All code links below pin that snapshot. Historical records describe their own dates and versions.

The decision rule is: **identify the actual owner and prerequisite, retain unresolved effects, and let independent work continue whenever its resources and authority are known to be independent**. Keeping the machine moving does not mean continually restarting the same operation, deleting holds, bypassing review, or declaring unobserved work successful.

## Findings that deserve implementation first

1. A terminal continuation can keep a lane classified as Progressing even though its monitor no longer visits it (E10).
2. When verification is stopped, an administrative hold can be rejected as Superseded while the unchanged candidate refreshes as Current. The inner verifier loop can repeat without yielding (V03). This is a static cross-component finding, not a newly reproduced incident.
3. A definitive merge refusal clears its landing intent but leaves an eligible candidate that can be selected again on the next tick (V11). Permanent refusals need a changed-prerequisite hold.
4. Missing pane telemetry permits a store-only stall verdict; the historical false-stall incidents establish why store silence is insufficient (E05).
5. Three unrelated story-local hard stops on already admitted lanes can stop an entire Full Auto run (E07). Shared breakers should count evidence of a shared failure, not simply accumulate local decisions.
6. Synchronous dispatch across runs and unbounded control-drain acknowledgement can delay unrelated control work despite per-run error handling (E03, E09).

These are implementation priorities within this proposal, **not assigned story priorities**. Existing conflict isolation, durable merge fences, cancellation, ownership checks and manual-mode behavior are protections to preserve.

## Common decision and retry rules

Evaluate in this order:

1. **Authority:** Is automation enabled for this project and this action? Does the exact generation, label revision, lease and owner still permit it? Manual mode produces diagnosis and explicit choices; it does not auto-resume because this document exists.
2. **External effects:** Is an operation in flight, ambiguous, or awaiting cleanup? Keep its durable intent and exclusive owner. Separate logical queue occupancy from physical process/resource custody.
3. **Evidence:** Is work progressing, legitimately waiting, proven failed, or unknown? Missing optional telemetry is unknown. Missing an authoritative sensor required for admission is a real admission hold.
4. **Scope:** Story → dependency subgraph → provider/capability → project → host. Widen only with evidence. Unknown shared ownership can legitimately require a host fence until independence is proven.
5. **Action:** Continue, observe, park, recover through the existing owner, or escalate. Every active controller gets a finite work budget and yields. A long-running healthy child need not be killed to satisfy a controller's response budget.
6. **Completion:** State the positive receipt or changed prerequisite that ends the hold. Timer expiry and acknowledgement alone are not recovery.

A proposed durable decision record should contain story/project/generation, owner and lease identity, operation and fault fingerprint, evidence refs, affected scope, held resources, disposition, first/last progress, next observation, retry count/budget, required prerequisite, escalation recipient/decision and completion proof. Keep retry budgets across daemon restart and acknowledgement. A changed generation does not erase an unresolved external effect or justify unlimited retries of the same infrastructure fault.

| Profile | Proposed bounded policy |
|---|---|
| **R0 — prerequisite hold** | Zero unchanged effect retries. Wake on a relevant dependency, exact head/base, credential/capability, review, label, policy or owner change. One coalesced notice; remain visible without repeated comment/notification writes. |
| **RO — observation** | One owner; read-only observations after 30, 60 and 120 seconds, then at most every five minutes or on a relevant event. Escalate after the initial bounded attempt set. Continuing passive observation does not grant mutation authority or clear custody. Respect server Retry-After and coalesce shared failures. These times are proposals, not measured optima. |
| **RT — proven transient failure** | Preserve the current verifier's three-total-attempt, 30-second-spacing ceiling where applicable. For new effect retries, require proof the prior effect did not occur or has settled; cap at one retry after 30 seconds unless an existing domain policy is stricter. Permanent auth, policy, integrity and causal failures use R0. No budget reset from an acknowledgement or restart. |
| **RC — cleanup/reconciliation** | Use the existing owner and its exact process/group/lease postconditions. Preserve its deadline across retries; do not reset the owned operation's clock. Retry idempotent reconciliation only after the previous controller has settled, at most three reconciliation attempts after 30/120/300 seconds (or a stricter existing policy), then attention while custody stays fenced. Never reap foreign processes or release on age alone. |
| **RQ — resource queue** | Keep one durable request ID and fairness age; use broker/holder events and the existing observation cadence. Do not spawn competing requests. Separate queue residence from execution timeout. An optional residence budget parks the logical job while retaining its queue identity and all physical custody. |

Repeated correlated faults may warrant a circuit breaker; unrelated dependency blocks do not. A proposed shared breaker key is capability/provider + operation + fault signature + relevant control revision. Authentication/integrity recovery requires a changed prerequisite, even after cooldown. Fairness must preserve declared priority semantics; show bypass age and use an explicitly designed quota, rather than silently inflating story priority.
