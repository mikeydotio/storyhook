## Council Decision

**Proposal:** Ship an explicit, transactional schema-lineage bridge, retain both reset contracts behind shared transactional ownership and workspace locking, and separate notification location discovery from verified process targeting.

The actual main schema stores reservations in story_resets.reservation, not stories.reset_json (HEAD:src/store/schema/0039_story_reset.sql:2), whereas dev uses story_resets.record_json (src/store/schema/0043_story_resets.sql:2): retain dev migrations 38–43 and add canonical 44, recognizing each supported historical state through migration names plus structural checks, verifying a backup before mutation, and bridging main atomically under BEGIN IMMEDIATE by preserving its landing rows, renaming its reservation table, installing missing dev structures, and recording canonical history plus original lineage without an observable version rewind; reject inconsistent or unknown combinations and replace numeric capability assumptions such as src/store/sqlite/landing.rs:10 with validated schema capabilities. Native reset explicitly renews force authorization and restores prior awaiting state (src/service/reset.rs:92,205), while card reset clears awaiting and removes its local branch (src/service/story_reset.rs:216), so keep these public contracts and recovery journals separate, but enforce pairwise exclusion among native reset, active card reset, engine reset, and landing at the final store transaction boundary, including imports and deletion, retaining every unresolved reservation rather than converting or clearing it. Card reset currently holds only a token-specific flock before quiescence and cleanup (src/service/story_reset.rs:137–179); after quiescence it must acquire the same repository/story WorkspaceLock used by native reset, revalidate pinned identities under that lock, pass ownership into destructive subprocesses, and retain it through completion, while preserving no-checkout operation, exact inode/Git/lease checks, and protected-artifact refusal; verification must likewise preserve certify→durable landing intent→external merge→reconciliation, with generation/block-revision checks and certification never interpreted as merge completion. Notification requires a location-only resource contract carrying canonical repository/worktree and recorded socket/window evidence, followed by enumeration of all panes and exact provider/process identity selection, then revalidation before interrupt, paste, and submit: globally changing active-pane selection would alter unrelated cleanup contracts, while the present active-only filter and cwd rejection demonstrably precede valid inactive-agent selection (src/service/resources/tmux.rs:89; src/service/resources/mod.rs:673). Minimum release evidence is executable upgrade coverage for shared schema 37, main 38/39, every dev 38–43, and fresh stores with populated pending operations and completed receipts; rollback/reopen/concurrent-upgrader and malformed-lineage cases; bidirectional reservation races, lock inheritance after parent death, and retry tests for both reset contracts; stale-generation/blocker and uncertain-merge recovery tests; and composed real-resource notification tests for inactive verified agents, recorded nonambient sockets, multiple matches, changed processes/panes, dead-pane identity, and refusal without respawn, followed by the central full suite.

**Why this won:** All three seats voted for B in round 1. It specifies the shared transaction boundary, lock acquisition after quiescence, resource-free reset compatibility, and uncertain-merge regression gates. Seat 3 research was excluded after a native spawn retry and late chair recording exhausted its retry deadline; seat 3 participated fully in voting. The panel ran through Codex native subagent orchestration using Astra at medium effort.

**Dissent:** None — unanimous
