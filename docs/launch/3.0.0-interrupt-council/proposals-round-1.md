# Round 1 Proposals

## Proposal A

**Summary:** Use durable intent revocation plus shared workspace ownership: replacement boundaries invalidate older pending deliveries, and a delivery holds inherited workspace ownership from transactional admission through external completion.

**Rationale:** The Pending→Attempting CAS currently protects only duplicate delivery, while Interrupt accepts any open story and discovers its session afterward (src/daemon/block_delivery.rs:145–203,244–254); current-block validation alone therefore cannot establish lifetime authority. Acquire the existing WorkspaceLock before claiming, retain it in helper descendants through completion, and require every dispatch, reset, and provider-session replacement boundary to supersede preexisting Pending intents transactionally before admitting its replacement; preserve acknowledged target semantics, coalesce obsolete Pending edges using current effective blocking and ordered delivery IDs, and finish already Attempting work before replacement becomes possible (src/service/workspace_lock.rs:14–76; src/store/block_delivery.rs:57–75). This can preserve schema44 and both reset journals without migration, but only with complete replacement-boundary coverage; legacy Pending rows lacking that guarantee must be conservatively superseded, Attempting recovery stays Uncertain without replay, and no external command runs inside a SQLite write transaction. Acceptance tests must pause before claim and after claim/before helper capture, race native reset plus replacement including a newly blocked replacement, exercise block/unblock/reblock and duplicate holds, retain exact socket/pane/PID/start identity checks, prove lock inheritance survives daemon death, and verify Resume reaches only the acknowledged interrupted session.

**Risks:** An unguarded provider restart or manual replacement defeats this schema-free contract; if such replacement remains supported, enqueue-time durable session authority and fail-closed helper enforcement are required instead.

**Confidence:** medium

## Proposal B

**Summary:** Use a serialized delivery-authority contract: claim and execute under the shared workspace lock, atomically retire older pending effects at every session-replacement boundary, and coalesce unclaimed transitions against current blocking; retain acknowledged session-bound Resume.

**Rationale:** src/daemon/block_delivery.rs:145 currently admits every OPEN Interrupt and :244 resolves its destination later; src/service/workspace_lock.rs:17 already supplies cross-process exclusion with inherited child ownership, so acquire that lock before the claim transaction and retain it through helper completion and acknowledgement without holding SQLite during external work. Every dispatch, repair redispatch, native reset and typed reset must retire the previous lifetime's pending effects under that same lock before replacement becomes possible; an already claimed effect finishes first, while rapid block/unblock before claim coalesces and transitions after claim are processed in order against the same protected session. Keep BlockDelivery.target's acknowledged meaning (src/store/block_delivery.rs:57), preserve exact process checks in plugins/story/lib/interrupt-agent.py:82, and fail closed for legacy pending authority that cannot be established; this uses existing statuses and locks without changing schema44 or either reset journal. Required barrier tests cover reset completion before claim, claim before reset completion with delayed helper capture, replacement already blocked, block/unblock/block, duplicate holds, interrupted daemon recovery without replay, same-session Resume versus replaced-session refusal, and inherited-lock survival after parent failure; these tests remain proposed, not executed.

**Risks:** This is complete only if every supported session-replacement path participates in the shared lock and pending-effect retirement; any uncovered path requires durable enqueue-time lifetime binding rather than an exemption.

**Confidence:** medium

## Proposal C

**Summary:** Use revocable pending authority plus shared workspace exclusion: supersede obsolete block episodes and pending deliveries before every session replacement, and hold inherited ownership from final delivery admission through external-effect quiescence.

**Rationale:** src/daemon/block_delivery.rs:145 currently admits every open Interrupt, while plugins/story/bin/story.sh:3612 captures whichever session exists later; StoryCleanupLease at src/domain.rs:524 identifies reusable resources rather than a unique provider lifetime. In src/service/block_delivery.rs:44, atomically supersede pending Interrupts whenever effective blocking ends, including transitions without Resume; admit only the current blocked active episode, and preserve already-started ordered Interrupt/Resume behavior with Resume bound exclusively to an acknowledged target. Acquire the existing cross-process WorkspaceLock before final admission and Pending-to-Attempting CAS, inherit it into the helper as supported by src/service/workspace_lock.rs:67, and require native reset, typed reset, dispatch, adoption, and every other replacement path to invalidate pending authority under that same lock before exposing another session; keep SQLite transactions closed during helper execution. Existing delivery statuses can encode this revocation without changing schema44 or repurposing target, but legacy pending rows lacking provable authority must be explicitly superseded rather than retroactively assigned to a discovered session; Attempting recovery remains Uncertain without replay. Acceptance tests must pause before claim, before helper capture, and before Escape while racing reset/replacement and block/unblock/reblock, cover restored prior awaiting and duplicate holds, prove orphan helpers retain exclusion, and verify unchanged exact PID/start/provider checks, session-bound Resume, lock contention retry, and honest timeout outcomes; these are proposed tests, not executed evidence.

**Risks:** This contract is complete only if every managed session-replacement path shares the lock and revokes pending authority; an uncovered replacement path requires a durable unique session binding rather than relying on reusable lease paths or current blocking alone.

**Confidence:** medium
